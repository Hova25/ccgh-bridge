# Mirror nothing in a repository that has no content yet

A repository that has just run `ccgh init` has workflows but no content directory: nobody has
written a domain yet. Its first push to a branch ran `ccgh bridge push`, which read the content
directory without asking whether it existed and failed with
`ENOENT: no such file or directory, scandir '…/docs/ccgh-bridge'`. Every other verb that reads
the tree, `sync`, `fixes`, `complete` and `reconcile`, would have failed the same way, so the
first thing an adopting repository saw was a red build. `ccgh validate` already treated that
state as nothing to check.

`ccgh bridge` now draws the same line before it reads anything. Without a content directory
and without `content` in `ccgh.json`, it prints that there is nothing to mirror and succeeds.
When `ccgh.json` names a content directory that does not exist, it refuses, since that is a
typo rather than a repository that has not started. `relink` reads GitHub alone and is not
concerned. The token and the repository are still resolved first, so a misconfigured workflow
is still reported before it has any content.
