# Release 1.1.5

A consumer that runs `prettier --check .` in CI fails as soon as it adopts ccgh 1.1.4. The
`ccgh-push.yml` workflow and the front matter `ccgh promote` writes are single-quoted, and
Prettier, at its default settings, wants double quotes. The fix is on `main`, but a consumer
pins `v1`, and `v1` cannot move onto a commit whose manifest still says `1.1.4`.

The manifest now says `1.1.5`. Merging this pull request tags `v1.1.5`, moves `v1` onto it and
publishes the GitHub release.

A consumer that already ran `ccgh init` with 1.1.4 has the single-quoted `ccgh-push.yml` on disk.
Running `ccgh init` again rewrites it. A specification that was already promoted keeps its
single quotes until it is next written, or until Prettier rewrites it with `--write`.
