# Release 1.1.0

Four fixes merged since 1.0.0 had not reached any consumer, because the installed plugin is
keyed by the version in `plugin.json` and that still said `1.0.0`: `ccgh init` writing the
lifecycle rules into `CLAUDE.md`, content paths and line endings working on Windows, fix pull
requests creating their issue, and reconcile no longer reporting fixes under review as
abandoned. A consumer that ran `/plugin update` got nothing new.

The manifest now says `1.1.0`, a minor version because each change adds behaviour and none
removes any. The tags follow the merge, as the README describes: `v1.1.0` on the merge commit,
and `v1` moved onto it. A test refuses a release tag on a commit whose manifest disagrees.

A consumer then updates the plugin and runs `ccgh init` once more, which is what writes the
`CLAUDE.md` block; its workflows need nothing, since the other three changes live in the action
they already call through `v1`.
