# Release 1.1.1

Three fixes to the hooks merged since 1.1.0 had not reached any consumer, because the
installed plugin is keyed by the version in `plugin.json` and that still said `1.1.0`: the
decision notice asking before harness edits whose path arrives absolute, the commit hooks
judging the directory a `cd` or `git -C` leads the commit into, and the command hooks applying
to the PowerShell tool as well as to Bash. A consumer that ran `/plugin update` got nothing new.

The manifest now says `1.1.1`, a patch version because each change repairs a rule that failed
to fire or fired on the wrong branch, and none adds a command or changes a contract. The tags
follow the merge, as the README describes: `v1.1.1` on the merge commit, and `v1` moved onto it.

A consumer only updates the plugin: the hooks live in the plugin, so neither `ccgh init` nor the
workflows need to run again.
