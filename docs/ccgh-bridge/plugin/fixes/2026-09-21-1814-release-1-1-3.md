# Release 1.1.3

A repository that had just run `ccgh init` failed its first `ccgh-push` run with `ENOENT` on
its missing content directory. The fix merged since 1.1.2, `ccgh bridge` finding nothing to
mirror in a repository that has no content yet, lives in the action consumers call through
`v1`, and `v1` cannot move onto a commit whose manifest still says `1.1.2`, since a test refuses
a release tag the manifest disagrees with.

The manifest now says `1.1.3`, a patch version because the change repairs a failure and adds
nothing. The tags follow the merge, as the README describes: `v1.1.3` on the merge commit, and
`v1` moved onto it.

A consumer needs to do nothing: its workflows call the action through `v1`, so the next run
uses the fix. A run that already failed can be re-run as it is.
