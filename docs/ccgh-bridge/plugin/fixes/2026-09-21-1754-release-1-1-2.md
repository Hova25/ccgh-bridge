# Release 1.1.2

Two fixes merged since 1.1.1 had not reached any consumer, because the installed plugin is
keyed by the version in `plugin.json` and that still said `1.1.1`: the commit hooks seeing a
commit behind a wrapper such as `rtk` or on a line of its own, and `ccgh init` installing a
repository's dependencies with the package manager its lockfile names rather than always with
Bun. A consumer that ran `/plugin update` got nothing new.

The manifest now says `1.1.2`, a patch version because both changes repair behaviour that was
already meant to hold, and neither adds a command or changes a contract. The tags follow the
merge, as the README describes: `v1.1.2` on the merge commit, and `v1` moved onto it.

A consumer updates the plugin, which is enough for the hooks. A consumer whose `ccgh.json` lists
`check` commands and that does not use Bun also re-runs `ccgh init`, which rewrites the install
steps of `ccgh-validate.yml`.
