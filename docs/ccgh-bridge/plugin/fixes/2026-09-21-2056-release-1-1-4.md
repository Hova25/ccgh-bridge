# Release 1.1.4

Everything merged into `main` since 1.1.3 is out of reach of a consumer, who pins `v1`, and
`v1` cannot move onto a commit whose manifest still says `1.1.3`, since a test refuses a release
tag the manifest disagrees with. That work is the adoption iteration, where `ccgh init` adopts
a repository on its own branch, `ccgh scaffold domain` creates a domain and a request for work
is classified before it starts, along with two fixes: the commit hook checking every script file
and refusing a check that cannot run, and no language being refused unless `ccgh.json` lists one.

The manifest now says `1.1.4`. This is the first bump since the `release` workflow learned to
follow the manifest, so the merge of this pull request is what tags `v1.1.4`, moves `v1` onto it
and publishes the GitHub release; should the workflow fail, the README gives the same steps by
hand.

A consumer needs to do nothing: its workflows call the action through `v1`, and the plugin
update reaches it through the marketplace.
